# Wisp 菜单栏不显示排查记录

日期：2026-11-13

## 问题现象

中文版安装到应用程序后运行正常，CPU 和内存菜单栏开关均开启，但用户截图确认顶部没有对应项目。此前只检查开关状态，未验证系统菜单栏实际显示。

## 调研过程

- 确认两个 NSStatusItem 已创建，isVisible 为 true，图标图像有有效尺寸；重建显示项不能解决。
- 使用临时文字和固定宽度入口排除图像绘制问题。诊断代码已撤回，安装包未替换为诊断版本。
- 系统设置的“允许在菜单栏显示”中没有独立 Wisp 条目，ChatGPT 为关闭状态。
- 只读解析系统 controlcenter 的 trackedApplications 数据，发现 app.wisp.Wisp.zh-hans-preview 被列为 com.openai.codex 的 menuItemLocations，且所属组 isAllowed=false。
- 退出诊断实例，从访达打开 /Applications/Wisp中文预览.app 后，归属仍保持不变。正常安装版已恢复运行。

## 当前状态

已恢复菜单栏显示。用户回复 1 确认后，已通过系统设置开启 ChatGPT 的菜单栏显示；系统随后新增独立的 Wisp中文预览 条目，状态为开启。Wisp 自身 CPU、内存显示保持开启。

## 拟修复方案

在系统设置 → 菜单栏 → 允许在菜单栏显示中开启 ChatGPT，然后验证 Wisp 的 CPU、内存项目是否出现及能否打开仪表盘。该开关也可能允许该组其他菜单栏项显示，影响超出 Wisp，需用户先确认。

## 验证结果与后续注意

根因证据：所属组为 com.openai.codex，isAllowed=false；从访达重新启动未解除既有归属。不要再把应用内部“已开启”当成系统实际可见的证据。不要在未经用户确认、没有备份和差异校验时改写系统内部偏好；不要重置整个控制中心。


## 修复后验证

- 系统设置界面确认 ChatGPT=on、Wisp中文预览=on。
- 只读核对系统记录，Wisp 独立分组 isAllowed=true。
- 窗口服务器确认 wisp.memory 与 wisp.cpu 均实际可见，各宽 63、高 30，位于外接显示器顶部，坐标分别为 (3015, 0)、(3078, 0)。
- 内置显示器对应菜单项仍为不可见，菜单栏空间较拥挤；不能把外接屏已显示等同于所有屏幕均显示。
- 安装的正常版本保持运行；没有安装诊断代码，没有重置控制中心，未提交 Git。


## 独立显示验证

用户询问能否解除与 ChatGPT 的关联。两者是独立应用；这里是 macOS 的菜单栏归属记录，不是程序依赖。

测试保持 Wisp 独立开关为 on，仅关闭 ChatGPT 后，wisp.cpu 与 wisp.memory 的实际菜单窗口消失。从访达重新启动 Wisp 后仍未恢复。系统同时保留 Wisp 独立允许记录，以及 ChatGPT 分组内包含 Wisp 的旧关联，因此单独开关尚不能解除该影响。

已把 ChatGPT 开关恢复 on，保留此前可用状态。下一步若用户确认，可先备份菜单栏偏好，再仅移除 ChatGPT 分组中的 Wisp 关联，保留独立 Wisp 允许记录，并刷新菜单栏验证；该方案涉及系统内部偏好，尚未执行，不能宣称已解绑。


## 最终解绑结果

用户明确确认后，已完成：

1. 备份原始偏好和 trackedApplications 原始数据到 `build/menu-bar-unlink-20261113-202244/`。
2. 使用偏好写入工具只更新 trackedApplications：从 com.openai.codex 分组的 menuItemLocations 中移除一条 Wisp 关联。独立 Wisp 允许记录和其他应用记录保持不变，写入后逐项校验。
3. 刷新 ControlCenter，再通过系统设置关闭 ChatGPT 的菜单栏显示，保持 Wisp 开启。
4. 验证 CPU、内存项目仍显示；随后退出并从访达重新启动 Wisp，再次确认 ChatGPT=false、Wisp=true、旧关联没有重新出现。
5. 重启后两个外接屏菜单窗口以 Wisp 包标识命名，均为可见，宽 63、高 30，位置 (3188, 0)、(3251, 0)。内置屏同名指标因空间不足仍为不可见，和解绑结果分开判断。

最终状态：系统旧关联已移除，Wisp 独立显示，ChatGPT 菜单栏开关已恢复关闭；不再需要开启 ChatGPT 才能显示 Wisp。没有修改程序代码或替换安装包。项目文档未提交 Git。

回退材料：完整偏好备份 `controlcenter-before.plist`、原始键值 `tracked-before.data`、修改后键值 `tracked-after.data` 及单条修改记录 `operation.json` 均在上述备份目录。必要时只回退该键，避免覆盖其他系统设置的新变化。
